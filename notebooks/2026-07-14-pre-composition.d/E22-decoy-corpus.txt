=================== THE CONSTRUCTION (a rendered problem) ===================

package p

type Ia interface { M() }

type Ta0 struct{}
func (Ta0) M() { m0(); }
type Ta1 struct{}
func (Ta1) M() { m1(); }
type TaD struct{}
func (TaD) M() { m2(); }

func sink(v Ia) {}

func makeIa(n int) Ia {
	switch n % 2 {
	case 0:
		return Ta0{}
	default:
		return Ta1{}
	}
}

func seed() int { return 0 }
func g0() { g1(); }
func g1() { g2(); sink(TaD{}); }
func g2() { g3(); }
func g3() { makeIa(seed()).M(); }
func m0() {}
func m1() {}
func m2() {}
func f0() { seed(); g0(); }
func d0() { d1(); }
func d1() { d2(); }
func d2() { d3(); }
func d3() { d0(); }

TaD implements Ia. TaD{} is ALLOCATED IN REACHABLE CODE (g0) and converted to Ia
by sink(). But makeIa can only ever return Ta0 or Ta1, and sink never invokes M.
So m2 -- TaD's leaf -- is NOT reachable from f0, while every syntactic cue says it
is. The syntactic rule that includes it ('TaD implements Ia, TaD is constructed,
this is an Ia dispatch') is exactly Class Hierarchy Analysis.

=================== THE THREE ALGORITHMS DISAGREE ===================

  static  f0 g0 g1 g2 g3 makeIa seed sink                 <- UNDER (no dispatch edge)
  cha     f0 g0 g1 g2 g3 m0 m1 m2 makeIa seed sink        <- OVER  (folds in m2)
  vta     f0 g0 g1 g2 g3 m0 m1 makeIa seed sink           <- EXACT
  TRUTH   f0 g0 g1 g2 g3 m0 m1 makeIa seed sink

Verified by direct probe on packages_iface_decoy/ifdecoy-d4k2-000.

=================== ORACLE (never vta) ===================

Truth is CONSTRUCTIONAL: the generator decides which types the factory can return.
CHA is therefore not the oracle here (it over-approximates); it is the CHECK:

    cha(f0)  ==  truth  UNION  {decoy leaves}

computed by the real Go toolchain from the rendered source, so it validates the
generator's graph model against the compiler's view. A mismatch throws the problem
away. VTA is PROBED and RECORDED, never trusted: whether vta is exact IS the
experiment's question, and an oracle that assumed it would decide the result by
construction.
